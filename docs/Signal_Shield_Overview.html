Signal Shield

Protecting Voice Recordings Against AI Cloning
Project Overview — July 2026

What Is This? (No Tech Jargon)

AI voice cloning tools can take a short recording of someone's voice and generate fake speech that sounds just like them. This is a real and growing threat — fraudsters can impersonate executives on phone calls, scammers can fake a loved one's voice, and anyone's voice can be used without their consent.

Signal Shield is an audio shield. You upload a voice recording, and it adds a tiny, inaudible watermark that confuses AI cloning tools. The audio sounds exactly the same to human ears, but when a cloning tool tries to learn from it, it gets garbage.

Think of it like this...

Imagine a forger trying to copy the Mona Lisa. Now imagine the museum adds an invisible UV pattern to the painting that doesn't change how it looks to visitors, but completely scrambles any photograph taken of it. The forger's camera captures a distorted mess, while museum-goers see the painting perfectly.

Signal Shield does the same thing to audio. Humans hear it perfectly. AI models "hear" a distorted version that's useless for cloning.

What Changed Recently

The original version used a simple, fixed transformation (like putting the same lock on every door). The new version uses AI-powered optimization — it custom-builds a unique perturbation for each audio file by actually attacking a voice recognition model and finding the most effective disruption. Same lock analogy, but now each lock is custom-fitted to the door.

Before: Static Phase Flip

  • Same transformation for every file
  • Might not fool modern cloning tools
  • Fast but generic
  • Based on assumptions about what models use

Now: Adversarial Optimization

  • Custom perturbation per file
  • Tested against a real AI model
  • Slower but targeted
  • Proven to change the AI's output

How It Works (Technical)

The Core Idea: Adversarial Perturbation

Voice cloning tools first convert audio into a speaker embedding — a compact numerical fingerprint (256 numbers) that captures what makes a voice unique. If we can corrupt this fingerprint without changing how the audio sounds, cloning fails.

Signal Shield uses PGD (Projected Gradient Descent) to find the optimal perturbation. PGD is the standard adversarial attack method in machine learning — the same technique used to fool image classifiers, adapted here for audio.

   Original Audio                    Protected Audio
   ┌─────────────┐                   ┌─────────────┐
   │ ~~~~~~~~~~~~ │   + delta         │ ~~~~~~~~~~~~ │
   │ ~~ waveform~ │ ───────────────> │ ~~ waveform~ │   Sounds identical
   │ ~~~~~~~~~~~~ │   (inaudible)     │ ~~~~~~~~~~~~ │   to human ears
   └──────┬───────┘                   └──────┬───────┘
          │                                   │
          v                                   v
   ┌─────────────┐                   ┌─────────────┐
   │   Speaker    │                   │   Speaker    │
   │   Encoder    │                   │   Encoder    │
   │ (Resemblyzer)│                   │ (Resemblyzer)│
   └──────┬───────┘                   └──────┬───────┘
          │                                   │
          v                                   v
   ┌─────────────┐                   ┌─────────────┐
   │  Embedding   │                   │  Embedding   │   Completely
   │ [0.23, 0.87, │    =/=            │ [0.91, -0.12 │   different
   │  -0.41, ...] │                   │  0.55, ...]  │   fingerprint!
   └──────────────┘                   └──────────────┘
The perturbation (delta) is tiny enough to be inaudible, but changes the AI's fingerprint entirely

The PGD Optimization Loop

The engine runs an iterative optimization that finds the best perturbation in 50 steps:

   Initialize: delta = zeros (no perturbation yet)

   Repeat 50 times:
   ┌──────────────────────────────────────────────────────────────┐
   │                                                              │
   │  1. FORWARD     audio + delta ──> mel spectrogram ──> LSTM   │
   │                                   ──> embedding              │
   │                                                              │
   │  2. LOSS        cosine_similarity(original_emb, new_emb)     │
   │                 "How similar are the two fingerprints?"       │
   │                                                              │
   │  3. BACKWARD    loss.backward()                              │
   │                 "Which direction should each sample move      │
   │                  to DECREASE similarity?"                     │
   │                                                              │
   │  4. UPDATE      delta -= alpha * gradient.sign()             │
   │                 "Take a small step in that direction"         │
   │                                                              │
   │  5. CLAMP       clip delta to [-epsilon, +epsilon]           │
   │                 "Keep it inaudible"                           │
   │                                                              │
   └──────────────────────────────────────────────────────────────┘

   Result: delta is optimized to maximally confuse the speaker encoder
           while staying within the imperceptibility bound
Each iteration pushes the embedding further from the original while keeping the perturbation inaudible

Key Parameters

Parameter Default What It Controls
pgd_steps 50 Number of optimization iterations. More = stronger protection, slower processing.
pgd_epsilon 0.01 Max perturbation amplitude (±1% of full scale). Keeps changes inaudible.
pgd_alpha 0.001 Step size per iteration. Smaller = more precise optimization.

The Differentiable Pipeline Challenge

PGD requires gradients — it needs to know "if I change this audio sample by a tiny amount, how does the embedding change?" This requires every step from audio to embedding to be differentiable (calculus-friendly).

The surrogate model (Resemblyzer) normally blocks gradients with torch.no_grad(). Signal Shield bypasses this by reimplementing the pipeline using differentiable PyTorch operations:

   Audio Samples (16kHz)
        │
        v
   ┌────────────────────────────┐
   │  torchaudio.MelSpectrogram │  Differentiable! (replaces librosa)
   │  n_fft=400, hop=160,       │
   │  n_mels=40, linear scale   │
   └────────────┬───────────────┘
                │
                v
   ┌────────────────────────────┐
   │  Split into 160-frame      │  Same windowing as Resemblyzer
   │  partial utterances        │  (1600ms chunks, 77-frame step)
   └────────────┬───────────────┘
                │
                v
   ┌────────────────────────────┐
   │  encoder.forward()         │  Differentiable! (bypasses no_grad)
   │  3-layer LSTM (256 hidden) │
   │  Linear (256 → 256)       │
   │  ReLU + L2 normalize       │
   └────────────┬───────────────┘
                │
                v
        256-dim Embedding         Gradients flow all the way back
                                  to the audio samples!
Every operation is differentiable, allowing gradients to flow from the embedding back to the audio input

Railway + Docker

Two containerized services from one repo, environment-variable configured

File Map — What Lives Where

Backend: The Engine

FilePurpose
adversarial_engine.py The core product. Contains the PGD loop, differentiable mel spectrogram, differentiable embedding computation, and lazy-loaded Resemblyzer encoder.
dsp_engine.py Public interface. Exposes apply_phase_protection(y, sr) which delegates to the adversarial engine. Keeps the API layer unchanged.
audio_io.py Loads audio from bytes (resamples to 22050Hz mono) and exports numpy arrays back to WAV bytes.
router.py Single API endpoint: POST /api/v1/protect. Validates upload, orchestrates load → protect → export, returns WAV.
config.py All settings via pydantic-settings. Configurable via SS_-prefixed environment variables.
main.py FastAPI app initialization, CORS middleware, health check endpoint.

Frontend: The Interface

FilePurpose
page.tsx Main page. State machine: idle → processing → done/error.
FileUploader.tsx Drag-and-drop + file input component.
ProcessingStatus.tsx Spinner and error display during processing.
DownloadButton.tsx Triggers browser download of the protected WAV.
api.ts Calls POST /api/v1/protect with FormData upload, returns blob.

Performance Note

PyTorch is CPU-intensive. Railway's free tier (512MB RAM) may struggle with the model. A paid plan ($5/month) with more CPU and RAM is recommended for production use. The CPU-only PyTorch build is used to minimize image size (~500MB vs ~2.5GB with CUDA).
